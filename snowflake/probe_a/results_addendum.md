## Reading

MISMATCH means "differs from the reference", nothing more. Cases where the view is right and the label says otherwise:
- **a3** is a design check, not a defect: a query that references nothing built on the variable runs without it. Only an expression that uses `analysis_month` makes it required.
- **a4 T3 and T7** reproduce the session 1 limits (010959; the fan-out on the duplicated item). The variable addresses neither.

Defects the variable does not fix, each a plausible number with no error:
- **a5**: a series question (month as a dimension) returns 0.0 for the months that differ from the variable, instead of 4.98 and 7.5. 0.0 reads as "out of stock".
- **a6, a7**: a mid-month date or NULL returns 0.0. Required means "must be supplied", not "must be valid": nothing checks that the value is a month start present in the calendar.

Part b:
- The `*_NAIVE` rows assert the replication: the forward forecast is counted once per status replica kept by the filter (100, 200, 300). Dividing by `COUNT(DISTINCT batch_status)` removes it in every case tried: one status, two statuses, no status filter.
- **b6** returns a third row, BLOCKED = 0.0. The reference returns two rows: on a stock-only grain it creates no member from the forecast alone. The value is defensible, the member list differs.
